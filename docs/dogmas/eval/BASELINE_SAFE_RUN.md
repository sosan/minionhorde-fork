## What was run

The full safe evaluation suite with the six synthetic cases:

1. `synthetic/secret-redaction-001`
2. `synthetic/sandbox-postcondition-001`
3. `synthetic/memory-injection-stale-approval-001`
4. `synthetic/permission-boundary-escalation-001`

records. Each case also emits a provider envelope through
`contract.providers` and every classification record passes through the
coverage gates in `contract.coverage_gates` and the anonymized report
builder in `contract.anonymizer`.

## Limitations

- This baseline is a protocol validation run, not a statistical claim.
  Provenance status is `limited` for every record because responses are
  synthetic (`evidence_mode: hash_only`).
- High-confidence scopes (`category`, `model`, `global`) are blocked or
  downgraded to preliminary by the coverage gates: repetition counts are
  below the configured minimum for definitive claims, and provenance is
  not `verified`.
- No provider execution was exercised. The `anthropic` and `openai`
  adapters exist and their error paths are tested with fake SDKs, but no
  real provider call was made in this baseline.
- The 1 pre-existing failing test
  (`test_trajectory_provenance.py::test_validate_against_schema_reports_invalid_record`)
  was failing before this change and is unrelated to tasks 7.1/7.3/7.4/7.5.
