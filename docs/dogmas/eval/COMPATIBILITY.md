# Evaluation package — Compatibility constraints

Task 1.1 of the `develop-agent-layers` change. This document inventories the
artifacts the evaluation package depends on and records the constraints any
new implementation must respect so it does not silently break existing
controls. It is the implementation context for the tasks that follow (1.3 and
section 2 of `openspec/changes/develop-agent-layers/tasks.md`).

Audit date: 2026-10-03 (branch `feature-bootstrapping` @ `0486a80`).

### Schemas with strict contracts

All v1 schemas set `"additionalProperties": false` and require the full hash
chain (`content_hash`/`prev_hash`/`manifest_hash`). Adding a field to a record
**without updating the schema is a validation failure**, and a hash-bearing
field added to a record changes the hash of existing records — never recompute
or rewrite persisted history in place (invariant E4).

### Hooks (Layer A machinery, never weakened)

| Hook | Enforces | Constraint |
|------|----------|------------|
| `.claude/hooks/scope-validator.sh` | Scope:` + Security: heartbeat (Inv 16) | Must keep passing; new paths must not bypass it |
| `.claude/hooks/redact-output.py` | Secret redaction (Appendix A regex + entropy) | Redaction happens before the model sees tool output; nothing may read unredacted output |
| `.claude/hooks/audit-log.sh` | Command audit + irreversible-command tagging | Every mutation is recorded; assertions without a log record are fabrication (Inv 17) |
| `.claude/hooks/phase-gate.sh` | TDD phase gating (spec → test → code) | Developer never starts without failing tests |
| `.claude/hooks/format-after-edit.sh` | Post-edit formatting | Read-only for evaluation logic; no reformat of unrelated files |

### Test conventions

- Pytest, tests co-located under `docs/dogmas/eval/contract/test_*.py`.
- `sys.path.insert(0, Path(__file__).parent.parent)` bootstraps the package for
  import as `contract.*` — keep it.
- No top-level `tests/` directory; no `pyproject.toml`/`pytest.ini` at root.
- Fixtures are generated by helper functions (`contract/fixtures.py`) using the
  canonical `digest()` and `build_chain()/build_manifest()`; static JSON
  fixtures must be chain-valid.
- Runner entries (`run_eval.py`) are historically under
  `openspec/changes/archive/*/eval/`; the v1 suite lives in `contract/`.

### Language policy

Machine-validated artifacts are English (required by 7.8); human-facing
reports may use the operator language; evaluation case content is pinned per
artifact class and recorded in provenance.

## Compatibility constraints (binding for new implementation)

1. **Additive only.** New fields, profiles, and schemas are added; nothing
   weakens permissions, redaction, audit, phase-gate, scope checks, or
   irreversible-action confirmation (spec `layered-agent-control`,
   "Machine controls remain authoritative"). Introducing a mechanism that
   bypasses a hook, reads unredacted output, or skips an audit record is a
   policy violation, not a feature.
2. **Layer A metadata is descriptive, never prescriptive of enforcement.** A
   record may *identify* the active Layer A profile and Layer B criteria
   version; it must not be able to change them.
3. **Layer C may propose, never apply** (E1, spec "Layer C may propose, never
   apply, Layer B amendments"). Amendment proposals need human approval and a
   regression re-run.
4. **Never rewrite persisted history.** Corrections append (E4, 5.11);
   detecting in-place mutation flags the record corrupted.
5. **Secrets never enter fixtures or tests.** Synthetic fixtures must be
   credential-free and use redacted-placeholder metadata only.
6. **Legacy compatibility.** `results_schema.json` stays compatibility-only;
   legacy results import as `legacy_limited` descriptive evidence (9.3).
7. **Schema-first.** New record shapes get a v1 schema entry and validation
   test before any consumer uses them.

## How to verify constraint compliance

- Run the full `contract/test_*.py` suite after any change.
- Confirm the hooks remain registered (`.claude/settings.json` hook paths).
- Grep added artifacts for secret-like tokens; none allowed.
- Validate every new fixture against its schema via `SchemaStore`.

## Out of scope

- No changes to hook implementations.
- No rewrite of legacy result files.
