# Selected memory — Refinement flow

Dogmas are refined from incidents. Incidents are not automatically dogmas.

## Three-level structure

1. **Episodic** — what happened in one situation. Kept briefly.
2. **Pattern** — several episodes share a cause. Reviewed quarterly.
3. **Dogma** — a pattern that survived Socratic critique and transfer testing. Lives in the CORE.

## Refinement flow

```
incidents
  -> grouping by cause
  -> proposed pattern
  -> evaluation case
  -> cross-model crystallization (if applicable)
  -> revised dogma (or new)
  -> mutations to verify transfer
```

## Prevention of normative inflation

Only promote a pattern to dogma if it represents a repeatable failure class. Each isolated incident does not create a rule.

## Memory structure per entry

- Situation: what was happening.
- Decision: what was done and why it was correct.
- Motive: reasoning reconstructed after critique.
- Transfer: future cases where the pattern should apply.

## Deprecation

When the context changes and the pattern stops being valid, the entry is marked as deprecated. Deprecated entries are not deleted; they are annotated with the reason and date.
